# Root Cause Analysis: The committed M_NmgORM master material drifts from its builder because it can only be rebuilt in a live editor

**Issue**: #204
**Date**: 2026-11-11
**Status**: Approved
**Author**: Rich Nunley
**Related Spec**: specs/148-let-one-finalized-asset-declare-several-material-variants/

## Root Cause

`scripts/unreal/build_master_material.py` `main()` always opens `UnrealMcpClient(args.url)` and sends `_MATERIAL_CODE` through `execute_python_code`, so the graph code runs only inside an editor that is already serving the Unreal MCP endpoint. Nothing in the repository can run `_MATERIAL_CODE` in a standalone engine process. A change to `_MATERIAL_CODE`, such as #148's `Tint` parameter, therefore never reaches the committed `M_NmgORM.uasset` unless someone rebuilds it by hand in a live editor.

## Affected Code

| File | Symbol / Area | Role |
|------|---------------|------|
| `scripts/unreal/build_master_material.py` | `main()`, module docstring | Only path to run `_MATERIAL_CODE` is the MCP client |
| `plugins/nmg-game-dev-ue-plugin/Content/Materials/M_NmgORM.uasset` | committed binary | Built from an older graph; lacks `Tint` |
| `tests/unit/test_build_master_material.py` | asset byte checks | Does not check the asset's parameter names |

## Fix Strategy

Add a `--headless` flag to `build_master_material.py`, mutually exclusive with `--url`. With `--headless`, `main()` never imports or constructs `UnrealMcpClient`, and runs these steps:

1. Resolve `UE_ROOT` (default `/Users/Shared/Epic Games/UE_5.8`). Require `Engine/Build/BatchFiles/Mac/Build.sh` and `Engine/Binaries/Mac/UnrealEditor-Cmd`, and the absolute path of `fixtures/dogfood.uproject` under the repository root. If any is missing, print `ERROR [master_material.headless_unavailable] <missing path>` with a remediation naming `UE_ROOT` and exit `3`.
2. Run `Build.sh DogfoodEditor Mac Development -Project=<abs dogfood.uproject> -WaitMutex -NoUBA`, so the editor binaries match the checkout. A non-zero exit prints `ERROR [master_material.build_failed] Build.sh exited <code>` and exits `3`.
3. Write `_MATERIAL_CODE` unchanged to `build_master_material_headless.py` in a `tempfile.TemporaryDirectory`.
4. Run `UnrealEditor-Cmd <abs dogfood.uproject> -ExecutePythonScript=<abs temp file> -DisablePlugins=ModelContextProtocol,EditorToolset,VibeUE -EnablePlugins=PythonScriptPlugin -unattended -nopause -nosplash -nullrhi -stdout -FullStdOutLogOutput`, capturing stdout and stderr. `-DisablePlugins` keeps the dogfood project's MCP server (configured for port 8000) and VibeUE from loading, so the process binds no MCP port and contacts no editor.
5. For each output line that contains `NMG_RESULT `, keep the text from that marker on, then pass the joined lines to `parse_nmg_result`. The existing exit-code mapping then applies: `0` prints `Built /nmg-game-dev/Materials/M_NmgORM`, and `1` reports a UE error or a missing result line. If the process exits non-zero with no `NMG_RESULT` line, the exit code is `1` and the message includes the exit status.

Both modes send the single `_MATERIAL_CODE` string, so they build the same graph. `_run()` still loads and clears an existing `/nmg-game-dev/Materials/M_NmgORM` instead of recreating it, so the rebuilt asset keeps its path and package name, and material instances keep their parent. The dogfood project mounts `../plugins`, so `/nmg-game-dev/` resolves to `plugins/nmg-game-dev-ue-plugin/Content/`, and the save writes the committed file in place. The engine's other output lands in the git-ignored `fixtures/{Binaries,Intermediate,Saved,DerivedDataCache}/`.

Once #148's `Tint` graph is in `_MATERIAL_CODE`, the implement step runs `uv run --group dev python scripts/unreal/build_master_material.py --headless` once, after `scripts/install-vibeue.sh` has populated the git-ignored `fixtures/Plugins/` that the `DogfoodEditor` build needs. It then commits the regenerated `M_NmgORM.uasset`.

Parameter names are checked against the asset's name table. The test looks for each name as a serialized name entry: a little-endian int32 length that counts the NUL, then the ASCII bytes, then a NUL (`struct.pack("<i", len(name) + 1) + name.encode() + b"\0"`). This avoids false matches on longer strings such as `BaseColorMap`.

## Changes

| File | Change | Behavioral reason |
|------|--------|-------------------|
| `scripts/unreal/build_master_material.py` | `--headless` mode as above; module docstring documents both commands, the exit codes, and that headless mode never contacts an editor | AC1, AC3, FR1, FR4 |
| `plugins/nmg-game-dev-ue-plugin/Content/Materials/M_NmgORM.uasset` | Regenerated by the headless mode from the `Tint` graph and committed | AC2, FR2 |
| `tests/unit/test_build_master_material.py` | Headless-mode tests with a fake `Build.sh` and `UnrealEditor-Cmd`; name-table checks on the committed asset | AC1–AC3, FR1–FR4 |
| `tests/bdd/features/master_material.feature`, `tests/bdd/test_master_material_bdd.py` | SCN004–SCN006 for AC1–AC3, reusing the unit-test helpers | AC1–AC3 |

## Blast Radius

The MCP mode (`--url`, the default) behaves as before. Material instances keep resolving their parent because the asset path and package name are unchanged. The regenerated asset changes only through the graph that `_MATERIAL_CODE` defines. The existing #101 byte checks for the default textures and `bUsedWithSkeletalMesh` must still pass on the regenerated file.

## Alternatives Considered

| Option | Decision | Reason |
|--------|----------|--------|
| Full editor `UnrealEditor-Cmd -ExecutePythonScript` on the dogfood project with the MCP plugins disabled | Selected | Runs the same editor-scripting APIs as the MCP path, saves into the mounted plugin content, and binds no MCP port |
| `-run=pythonscript` commandlet | Rejected | Commandlets skip parts of editor startup that `MaterialEditingLibrary` relies on |
| A temporary content-only `.uproject` | Rejected | The engine's prebuilt `UnrealEditor` would not match the plugin binaries built for `DogfoodEditor` |
